# منهجية فحص دفترة واكتشاف المنطق المخفي

## المبادئ
1. **صندوق أسود:** لا نرى الكود، بل نرى الأثر. ننفّذ عملية، ونقارن الحالة قبلها وبعدها.
2. **حساب تجريبي منفصل فقط.** شركة وهمية، وبريد مستقل، وأعلى باقة. لا يُستخدم حساب أريس الحقيقي أبداً.
3. **دفترة مرجع وليست المرجعية.** كل قاعدة نكتشفها تُقيَّم مقابل المعايير الدولية (IFRS 18 والمعايير المعتمدة من SOCPA) ولوائح هيئة الزكاة والضريبة والجمارك وأفضل ممارسات SAP وOracle وD365 وOdoo.
4. **لا ادعاء بلا دليل:** لقطة شاشة، أو مخرَج تقرير، أو استجابة API، تُحفظ في `docs/evidence/daftra/<module>/`.

## دورة الاكتشاف لكل سيناريو
| الخطوة | ماذا نفعل | المخرج |
|---|---|---|
| 1. السيناريو | نختار حالة: عادية، أو حدّية، أو خطأ | رقم السيناريو `SC-<MOD>-NNN` |
| 2. لقطة قبل | الأرصدة، والمخزون وتكلفته، وآخر القيود، والترقيم | صور ومخرجات |
| 3. التنفيذ | العملية في دفترة | لقطات الخطوات |
| 4. لقطة بعد | ما الذي تغيّر؟ القيد الناتج؟ المخزون؟ الحالة؟ ما الذي قُفل؟ | صور ومخرجات |
| 5. القاعدة | صياغة القاعدة المكتشفة | `BR-<MOD>-NNN` (مقترحة) |
| 6. التقييم | هل هي صحيحة محاسبياً ونظامياً؟ وكيف تطبقها الأنظمة العالمية؟ | اعتماد، أو تعديل، أو تحسين |
| 7. الاعتماد | مراجعة مدير المنتج | الحالة: معتمدة |
| 8. الاختبار | تحويلها إلى سيناريو اختبار آلي في نظامنا | رقم الاختبار |

## قوالب السيناريوهات الإلزامية لكل موديول
- **الإنشاء، والتعديل قبل الترحيل، والتعديل بعد الترحيل، والحذف بعد الترحيل** (هل يُسمح؟ وما الأثر؟)
- الإلغاء والعكس، والمرتجع الجزئي والكلي
- الدفع الجزئي، والزائد، والمقدّم
- الخصم على السطر مقابل الخصم على الإجمالي، والسعر شامل الضريبة مقابل غير شامل
- التقريب: على مستوى السطر أو الإجمالي، وعلى خانة واحدة أو خانتين أو أربع خانات
- الوحدات المتعددة وتحويلها
- البيع بالسالب في المخزون
- العملات الأجنبية
- التاريخ الرجعي، والفترة المقفلة
- الصلاحيات: مستخدم محدود الصلاحية يحاول تنفيذ العملية
- الترقيم: التسلسل، والفجوات عند الحذف أو الإلغاء، والترقيم حسب الفرع
